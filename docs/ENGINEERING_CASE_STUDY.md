# ScaraScope AI: Engineering evidence case study

## Problem

LLMs can produce persuasive financial text without correct units, consistent reporting periods, or source-backed numbers. Financial research requires a clear separation between deterministic financial arithmetic, retrieval, and optional language generation.

## Approach

- Modular FastAPI service delegates SEC retrieval to `data/sec/` and financial math to `finance/`.
- Finite research plans and separate Ollama/Groq adapters prevent Discord or HTTP logic from owning domain calculations.
- Privacy-aware routing prevents sending `local_only` requests to cloud, including after local model outages.
- A fixed historical SEC-derived numerical dataset tests arithmetic, units, reporting periods and source metadata offline.
- Provider stubs simulate failures without calling external services or pretending to benchmark live availability.
- A separate `/engineering` browser view displays case-level evidence, source links and benchmark history.

## Demonstration procedure

1. Open `/` and use `DEMO` to show the explicitly fictional no-key research workflow.
2. Visit `/engineering` and run the offline evaluation. Compare the historical financial suite, synthetic retrieval suite and fault tests; they have **different denominators and meanings**.
3. Open Microsoft's FY2024 and Apple's FY2023 10-K source links from the Engineering Lab to inspect the recorded reference amounts.
4. Open an individual case to see expected vs. observed results.
5. Run `python -m pytest -q` locally and inspect GitHub Actions artifacts to verify the test run and its dataset fingerprint.
6. For an engineering discussion, demonstrate tests that deliberately alter a financial value, reporting period, source URL, or evidence citation and observe rejection.

## Evidence, not claims

Every displayed score should be generated by the current code. The first benchmark datasets are deliberately small. Fixed historical arithmetic accuracy is **not** general financial question-answer accuracy, and synthetically simulated cloud outages are **not** measured provider uptime. The browser does not show invented cost/latency numbers.

## Next research questions

- How often does the live SEC XBRL extraction choose a comparable fiscal period across different issuers and taxonomies?
- Does embedding-based retrieval beat lexical retrieval on a held-out, annotated filing corpus?
- Do Groq and Ollama differ in grounded-answer correctness on identical questions, and how does fallback affect privacy, latency and price?
- Can claim-level verification detect qualitative falsehoods beyond missing citations and copied-number inconsistencies?

Current status: **v0.4 portfolio prototype**, not a production investment advice service, audit system, or full-document fact checker.


## v0.8: keeping held-out scores honest

A second review is an optional, strict benchmark policy rather than an assertion that data has been independently validated. The audit lists reviewer-metadata gaps, and `--require-second-review` excludes incompletely checked cases. Regression checks reject any changed question-set hash, source accession/excerpt hash, method set, review policy, or sample denominator; no unreviewed real-filing result is promoted to a portfolio score. Syntactic numeric-unit checks supplement citation labels but cannot verify qualitative meaning. See [REVIEW_PROTOCOL.md](REVIEW_PROTOCOL.md) for exact acceptance criteria.
